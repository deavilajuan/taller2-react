## 🎯 Objetivo

Reforzar la teoría de **React** mediante una investigación autónoma. Este taller te pide construir tus propias definiciones —con tus palabras— sobre qué es React, qué problema resuelve, cuáles son sus componentes principales, por qué es importante en la industria y qué empresas grandes lo usan en el mundo real.

> 💡 **Espíritu del taller:** lo importante no es copiar texto de internet, sino **entender, resumir con tus palabras** y poder explicarlo. Las respuestas copiadas sin comprender no cumplen el objetivo.

## 📌 Instrucciones generales

1. Investiga usando **fuentes confiables** (sugerencias al final del documento; no te limites a ellas).
2. Responde los **5 puntos** del taller, en el orden presentado.
3. **Cita las fuentes** que usaste (puede ser con enlaces al final del documento).
4. Escribe con **tus propias palabras**; está permitido incluir fragmentos de código como ejemplos (debes explicarlos, no solo pegarlos).
5. Entrega un **PDF o Markdown** subido a un repositorio de GitHub. Al terminar, envía el **enlace del repositorio** (ver sección "Cómo entregar" 👇).

## 📝 Puntos del taller

### Punto 1 · ¿Qué es React?

Investiga y define con tus palabras:

- ¿Qué es React y para qué sirve dentro del desarrollo web?
- ¿Quién lo creó y en qué año apareció?
- ¿Es una **librería** o un **framework**? Explica la diferencia y justifica tu respuesta.
- ¿Qué significa que React sea **declarativo**?

### Punto 2 · ¿Qué problema resuelve React?

- ¿Cuál era la dificultad principal de construir interfaces con JavaScript "a mano" (manipulando el DOM)?
- Explica la diferencia entre el enfoque **imperativo** y el enfoque **declarativo**.
- ¿Cómo ayuda React a mantener la interfaz **sincronizada** con los datos (el estado)?
- ¿Qué rol juegan los **componentes reutilizables** en la solución de ese problema?

### Punto 3 · Principales componentes de React

Para **cada uno** de los siguientes elementos, escribe:

- **Definición** (con tus palabras)
- **Características principales**
- **Ejemplo de código** si aplica (con una breve explicación de qué hace)

Elementos a desarrollar:

1. **Componentes** (qué son y cómo se crean)
2. **JSX** (qué es y sus reglas básicas)
3. **Props** (qué son y para qué se usan)
4. **Estado** (`useState`: qué es y cómo cambia la interfaz cuando el estado cambia)
5. **Eventos** (`onClick`, `onChange`: cómo el usuario interactúa con la interfaz)

> ✍️ Puedes usar fragmentos cortos de código como los que aparecen en la documentación oficial de React.

### Punto 4 · Importancia de React en la industria

Investiga y explica:

- ¿Por qué tantas empresas eligen React para sus productos web?
- ¿Qué aporta React al **ecosistema** de desarrollo (herramientas que lo rodean: empaquetadores, frameworks basados en React, etc.)?
- ¿Qué papel juegan su **comunidad** y su mantenimiento (quién lo mantiene hoy)?
- ¿Por qué es una habilidad **relevante** para un desarrollador front-end hoy en día?

### Punto 5 · Grandes empresas que utilizan React

- Menciona **al menos 2 empresas reconocidas a nivel mundial** que usen React en sus productos.
- Para cada una: describe **en qué producto o sección** lo usan y por qué es un caso relevante.
- **Cita la fuente** de donde tomaste la información (página oficial, artículo, conferencia, etc.).

> 🧠 Pista: piensa en redes sociales, plataformas de streaming, aplicaciones de transporte o de hospedaje… Muchas de las apps que usas a diario están construidas (al menos en parte) con React.

## 🚀 Cómo entregar (GitHub, paso a paso)

1. Crea un **repositorio nuevo** en GitHub (público o privado, a tu elección) con un nombre como `taller2-react` (o similar).
2. Sube tu archivo de entrega dentro del repositorio: `taller-2.md` (si es Markdown) o `taller-2.pdf` (si es PDF).
   - En la web de GitHub: botón **Add file → Upload files** y arrastra tu archivo.
   - O si prefieres por terminal:
     ```bash
     git init
     git add taller-2.md      # o taller-2.pdf
     git commit -m "Taller 2 Corte"
     git branch -M main
     git remote add origin <url-de-tu-repositorio>
     git push -u origin main
     ```
3. Verifica que el archivo se vea bien en el repositorio.
4. **Entrega el enlace del repositorio** en la plataforma del curso antes de la fecha límite.

> ⚠️ **Importante:** revisa la fecha y la hora de entrega. Los trabajos fuera de plazo se evalúan según el reglamento del curso.
